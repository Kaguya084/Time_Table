# 校园日程助手 · 网页端

> 把散落在教务系统、微信群、学习通、班群里的日程，变成 iPhone 原生日历里一条条带闹钟的提醒。

## 这是什么

校园里的时间信息散落在四五个地方、格式各异，全靠脑子记。手机日历能提醒，却认不出群聊里的"10 月 31 号比赛"——**非结构化信息进不了日历，这才是断点**。

本项目的定位很明确：**不做日历，做日历的上游。** iOS 原生日历已经够好，缺的只是谁来喂数据。于是做成一条流水线：

- **连小理（AI 搭档）负责「想」**：解析通知、规划时间、识别冲突、生成结构化数据。
- **网页只负责「看和点」**：打包解析请求、给人逐条核对、导出 `.ics`。网页里没有智能——不解析、不规划、不生成。

判断标准：拿掉连小理，剩下的部分与原生日历无异。

## 功能特性

- **四类日程，各自独立日历**：课表 / 活动 / DDL / 个人，导出后是四个可在 iPhone 上分别开关的日历。
- **课表只读，其余可改**：课表有权威源（教务系统），改了也没用；活动、DDL、个人没有权威源，支持增删改。
- **先预览、后写入**：连小理的解析结果先出预览，逐条人眼核对再确认导入——第一版就靠肉眼抓出过一条节次错误的课。
- **信息不全不编造**：时间 / 地点缺失时标「待确认」而不是替你编一个，保证结果可信。
- **重复日程是一条规则**："每个工作日 6:40 早训"生成带 `RRULE` 的一条系列，不是几十条独立事项。
- **数据全在本机**：不联网、不经过任何服务器，所有数据存在浏览器本地。

## 使用流程

1. **导入课表**：电脑打开网页 → 「复制课程表解析请求」，连同教务系统导出的 PDF / 截图发给连小理 → 它返回 JSON → 粘回网页 → 先预览逐条核对 → 确认导入。
2. **导入事项**：把群通知原文粘进网页 → 生成解析请求（自动带上"今天第几周、第一周周一日期"）→ 连小理返回事项 → 预览核对 → 确认导入。
3. **手机接力**：电脑端「复制全部数据」，手机打开同一网址「粘贴并恢复」。两端数据各自独立，靠这一步接力（数据按网址隔离）。
4. **导出到 iPhone**：按类导出四个 `.ics`（课程表 / 活动 / DDL / 个人），用文件 App 或邮件导入 iPhone 日历，得到四个可开关的日历。

> ⚠️ **iOS 导入只有「新增」、没有「更新」。**
> 某类日程改过后，先在 iPhone 上删掉那一类日历，再重新导入该类 `.ics`。整套流程就是按这个语义设计的。

## 按钮功能一览

按页签分组，列出界面上每个按钮的作用。

### 顶部（所有页签通用）

| 按钮 | 作用 |
| --- | --- |
| **日程表 / 新增事项 / 其他** | 三个页签，切换下方视图。 |
| **导出 ics** | 进入导出视图，按类导出四个 `.ics`。 |
| **‹ / ›** | 周视图里切到上一周 / 下一周。 |

### 日程表

| 按钮 | 作用 |
| --- | --- |
| **课表 / 活动 / DDL / 个人**（四类开关） | 控制周视图里显示哪些类别的日程。 |
| **复制课程表解析请求** | 把"当前第几周、第一周周一"等上下文打包成一段请求文本，复制到剪贴板，发给连小理要 JSON。 |
| **复制请求** | 再次复制已生成的课程表请求文本。 |
| **解析并预览** | 把从连小理粘回来的课程表 JSON 解析出来，先出预览供逐条核对。 |
| **确认覆盖** | 预览核对无误后，用这批课程**覆盖**现有课表。 |
| **导入 ics 文件 → 作为课表导入** | 选一个 `.ics`，按"课程名 + 星期 + 起止时间"合并、反推周次，**覆盖**课表（同学间共享用）。 |
| **导入 ics 文件 → 作为事项追加** | 把 `.ics` 里的事件原样**追加**到备忘录（默认"活动"类）。 |
| **确认追加** | 确认把导入的 ics 事件追加进备忘录。 |
| **时间范围**（今天 / 本周 / 未来…） | 事项列表按时间范围筛选。 |
| **活动 / DDL / 个人**（类筛选） | 事项列表按类别筛选。 |
| **批量修改** | 进入批量模式，可勾选多条事项统一改类型 / 优先级。 |
| **全选 / 清空** | 批量模式下，选中全部 / 清空选择。 |
| **应用 / 完成 / 删除 / 退出批量** | 批量模式里：应用修改 / 标记完成 / 删除选中 / 退出批量模式。 |
| 每条事项右侧 **✓** | 切换"已完成"。 |
| 每条事项右侧 **×** | 删除该条事项。 |
| 每条事项右侧 **编辑** | 展开该行改时间 / 时长 / 地点 / 提醒，再点**保存 / 取消**。 |

### 新增事项

| 按钮 | 作用 |
| --- | --- |
| **班级群通知 / 公众号推送** | 选择本次通知的来源类型（影响解析请求的上下文提示）。 |
| **生成解析请求** | 把粘贴的群通知原文 + "今天第几周"等上下文，打包成请求文本。 |
| **暂存原文** | 把通知原文存在本机，关掉网页也不丢，下次接着处理。 |
| **复制解析请求** | 复制生成的请求文本，发给连小理。 |
| **解析并预览** | 把连小理返回的 JSON 解析出来，先出预览供逐条核对。 |
| **手动触发 · 标记此刻已汇总** | 把"现在"标记为最后一次已汇总时刻，避免连小理重复推送已汇总过的内容。 |
| **确认导入** | 预览核对无误后，把这批事项导入备忘录。 |
| **添加 / 批量生成** | 手动填表添加一条事项（支持多行批量生成）。 |
| 待导入列表每条 **生成请求 / ×** | 把该条重新打包发给连小理核改 / 从列表移除。 |

### 其他

| 按钮 | 作用 |
| --- | --- |
| **复制全部数据** | 把所有课表 / 事项 / 记录导出成一段 JSON，用于换设备、换网址时迁移。 |
| **粘贴并恢复** | 把"复制全部数据"得到的 JSON 粘进来，恢复到本机。 |
| **清空本机全部数据** | 删除本机全部课表 / 事项 / 记录（不可恢复，先备份）。 |
| **为老数据补空白默认值** | 升级后若"日程表"打不开，点它自动补齐旧数据缺失的字段并写回本机。 |

> 每条待确认的课程 / ics 预览里，也有 **删** 按钮可移除单条后再确认。

## 部署

本仓库是一个**零依赖、零构建的单文件静态站**——整个应用就是 `index.html`（HTML + CSS + JS 全部内联），不引用任何外部资源、不发任何网络请求。

直接用 `index.html` 作为 GitHub Pages 的根页面即可：

1. 把 `index.html` 放进仓库根目录（或 `docs/`，并在 Pages 设置里选择它）。
2. 仓库 **Settings → Pages** → 选择对应分支与目录。
3. 等待构建完成，访问 `https://<用户名>.github.io/<仓库名>/`。

网页本体是「空壳」：不含任何课表 / 个人信息，所有数据由使用者自行导入。

## 数据与安全

- **不收集**：没有后端、没有统计、没有任何网络请求。打开网页源码搜不到一个 `fetch` 或外链。
- **本地存储**：课表、事项、基线记录都存在浏览器 `localStorage`，按网址隔离——换网址等于换一份空数据。
- **迁移**：换设备或换网址前，用「其他 → 数据备份 / 迁移」里的「复制全部数据」导出，到新地址「粘贴并恢复」。
- **老数据修复**：若用旧版存过数据、升级后「日程表」打不开，去「其他」页签点「为老数据补空白默认值」，会自动补齐缺失字段并写回本机。

## 目录说明（开发者）

- `index.html` —— 完整应用代码（单文件，可直接部署）。开发仓库中它对应 `dist/index.html`，是唯一的编辑源；网页严格只做"打包—核对—导出"三件事。
- 解析请求里的字段规范与字段集以代码内注释及提示词为准。
